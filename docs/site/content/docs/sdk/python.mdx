The official MessageX Python SDK is an **asyncio TCP client** distributed on PyPI as `messagex-client`. Its import package is named `messagex`.

## Availability

The SDK source and release workflow are in this repository. The first public PyPI release is being prepared; until the release is announced, install from the `tilak` branch:

```bash
python -m pip install "git+https://github.com/sameeryadav05/MessageX.git@tilak#subdirectory=packages/python-sdk"
```

After the package is published, install the stable distribution from PyPI:

```bash
python -m pip install messagex-client
```

Requires **Python 3.9 or newer**. The package has no third-party runtime dependencies. You still need a running MessageX broker and valid broker credentials. The standard Docker deployment exposes the broker on `localhost:5678`.

## Quick start

Set credentials as environment variables rather than hard-coding them:

```bash
# Linux / macOS
export MESSAGEX_USER="your-username"
export MESSAGEX_PASSWORD="your-password"
```

PowerShell:

```powershell
$env:MESSAGEX_USER = "your-username"
$env:MESSAGEX_PASSWORD = "your-password"
```

### Consumer

```python
import asyncio
import os
from messagex import MessageX

async def handle(message):
    print("Received:", message.body)
    await message.ack()

async def main():
    async with MessageX(
        host="127.0.0.1",
        username=os.environ["MESSAGEX_USER"],
        password=os.environ["MESSAGEX_PASSWORD"],
    ) as client:
        await client.exchange.declare("orders.exchange", "direct", durable=True)
        await client.queue.declare("orders", durable=True)
        await client.exchange.bind(
            "orders.exchange", "orders", "orders.created"
        )
        await client.consume("orders", handle)
        await asyncio.Event().wait()

if __name__ == "__main__":
    try:
        asyncio.run(main())
    except KeyboardInterrupt:
        pass
```

### Producer

```python
import asyncio
import os
from messagex import MessageX

async def main():
    async with MessageX(
        host="127.0.0.1",
        username=os.environ["MESSAGEX_USER"],
        password=os.environ["MESSAGEX_PASSWORD"],
    ) as client:
        result = await client.publish(
            "orders.exchange",
            {"orderId": "ORD-1001", "status": "created"},
            routing_key="orders.created",
        )
        print("Routed to", result.routed_queues, "queue(s)")

asyncio.run(main())
```

Run the consumer first, then run the producer in another terminal.

## Core capabilities

- Async connection lifecycle with context-manager support.
- Queue and exchange declaration/deletion.
- Direct, fanout, topic, and headers exchanges.
- Bind and unbind operations.
- JSON-serializable message publishing with optional headers.
- Callback-based consumers and explicit ACK/NACK.
- Delivery-count-based retry and dead-letter queue configuration.
- Typed message objects, result objects, and SDK exceptions.
- Client events for connection lifecycle, messages, warnings, and consumer errors.

## Delivery handling

The SDK does not automatically acknowledge messages. ACK only after successful processing:

```python
async def handle(message):
    try:
        await process_order(message.body)
        await message.ack()
    except TemporaryError:
        await message.nack(requeue=True)
    except Exception:
        await message.nack(requeue=False)
        raise
```

The broker currently uses a prefetch count of one per consumer connection. Requeued messages can be delivered more than once, so make handlers idempotent when they perform external side effects. The broker supports a maximum delivery count and a configured dead-letter queue.

## Connection options

```python
client = MessageX(
    host="127.0.0.1",
    username="app-user",
    password=os.environ["MESSAGEX_PASSWORD"],
    port=5678,
    client_name="billing-service",
    connect_timeout=10.0,
    request_timeout=15.0,
    max_frame_size=1_048_576,
)
```

Use `async with MessageX(...)` to close the connection automatically, or call `await client.connect()` and `await client.close()` for manual lifecycle management.

## Important limitations

- The SDK does not automatically reconnect or restore consumer subscriptions after a disconnect; the application must reconnect and subscribe again.
- The broker TCP transport currently does not provide TLS encryption. Use a private network, VPN, or SSH tunnel for remote connections.
- ACK/NACK does not create a distributed transaction with your application database.
- The current consumer prefetch count is one per connection and queue.
